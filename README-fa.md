# آروان‌شیر (ArvanShare)

آروان‌شیر یک **شبکه اجتماعی خصوصی و بدون سرور (serverless)** برای حلقه کوچکی از دوستان، خانواده یا یک تیم است. این برنامه هیچ سرور بک‌اند یا دیتابیسی ندارد — در عوض، **تمامی داده‌ها (پست‌ها، کامنت‌ها، لایک‌ها و فایل‌های پیوست) مستقیماً روی یک باکت Object Storage آروان‌کلاد** (سازگار با S3) ذخیره می‌شوند.

کلاینت‌ها مستقیماً به باکت متصل می‌شوند و از یک ساختار فایل یکسان و امن در برابر تداخل (race-condition safe) استفاده می‌کنند.

## 📱 اپلیکیشن اندروید (Kotlin / Jetpack Compose)

یک اپلیکیشن نیتیو و مدرن اندروید با قابلیت آفلاین-فرست (offline-first).
متادیتا پست‌ها در دیتابیس محلی Room کش می‌شود تا فید بلافاصله پس از باز شدن برنامه بارگذاری شود، و رسانه‌ها با کیفیت اصلی در صورت نیاز از طریق Coil دانلود می‌شوند.

**برای اجرا:**
۱. پروژه را در Android Studio باز کنید.
۲. ماژول `app` را بیلد و اجرا کنید.
۳. در اولین اجرا، نام نمایشی خود و اطلاعات باکت آروان‌کلاد را وارد کنید.

*(یا می‌توانید فایل `.apk` را مستقیماً از صفحه GitHub Releases دانلود کنید).*

## 💻 اپلیکیشن دسکتاپ ویندوز (Python / Tkinter)

یک کلاینت دسکتاپ با امکانات کامل همراه با رابط کاربری حالت تاریک (dark-mode)، فید کارتی، و پشتیبانی از فایل‌های پیوست.

**برای اجرا (نسخه پرتابل):**
۱. فایل `ArvanShare-*.exe` را از صفحه GitHub Releases دانلود کنید.
۲. برای اجرا روی آن دوبار کلیک کنید — نیازی به نصب پایتون نیست.
۳. تنظیمات به صورت محلی در کنار فایل `.exe` (یا در مسیر `%LOCALAPPDATA%`) ذخیره می‌شوند.

**برای اجرا (از سورس کد):**
۱. مطمئن شوید که Python 3.10 یا بالاتر نصب شده است.
۲. روی فایل `python\ArvanShare.bat` دوبار کلیک کنید.
۳. این اسکریپت شما را برای ایجاد محیط مجازی و نصب وابستگی‌ها (`boto3`) راهنمایی می‌کند.

*(همچنین می‌توانید به صورت دستی دستور `.venv\Scripts\python.exe desktop.py` را اجرا کنید)*

## 🛠️ رابط خط فرمان (CLI)

یک ابزار CLI مرجع برای مدیریت فید یا ساخت پست به صورت خودکار (automation).

**راه‌اندازی:**
```bash
cd python
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
copy config.example.ini config.ini
# فایل config.ini را با اطلاعات خود ویرایش کنید
```

**نحوه استفاده:**
```bash
.venv\Scripts\python arvanshare.py init-structure
.venv\Scripts\python arvanshare.py upload-post --text "سلام به همه!" --as Ali
.venv\Scripts\python arvanshare.py list-posts
.venv\Scripts\python arvanshare.py get-post <post_id>
```

## ☁️ تنظیم باکت آروان‌کلاد (بک‌اند بدون سرور)

برای استفاده از آروان‌شیر، به یک باکت اشتراکی نیاز دارید که تمام داده‌ها در آن ذخیره شوند.

۱. به [پنل کاربری آروان‌کلاد](https://panel.arvancloud.ir) بروید -> **فضای ابری (Object Storage)**.
۲. **یک صندوقچه (باکت) ایجاد کنید** (مثلاً `my-family-share`).
۳. **آدرس S3 Endpoint** را یادداشت کنید (مثلاً `https://s3.ir-thr-at1.arvanstorage.ir`).
۴. به بخش **کلیدهای دسترسی (API Keys)** بروید و یک جفت کلید تولید کنید (**Access Key** و **Secret Key**).
۵. این کلیدها را با دسترسی خواندن/نوشتن (Read/Write) به باکت جدید خود متصل کنید.

این ۴ بخش اطلاعات (آدرس Endpoint، نام باکت، Access Key و Secret Key) را به همه افراد حلقه خود بدهید. آن‌ها این اطلاعات را در اولین اجرای برنامه وارد خواهند کرد.

## 🏗️ معماری و مدل داده‌ها

کل این شبکه اجتماعی بر روی کلیدهای (Keys) فضای ابری S3 پیاده‌سازی شده است.

```text
/
├── posts/
│   ├── 20260806_120000000_ali_post.json    # متادیتا (متن، نویسنده، زمان)
│   └── 20260806_120000000_ali_image.jpg    # فایل رسانه پیوست شده
└── comments/
    └── 20260806_120000000_ali/             # پوشه برای تعاملات این پست
        ├── like_reza.txt                   # فایل نشانگر خالی = یک لایک
        └── 20260806_120530_reza.json       # فایل JSON کامنت
```

### ایمن در برابر تداخل (Race-condition safe)
از آنجا که هیچ دیتابیس مرکزی برای مدیریت همزمانی وجود ندارد، این مدلِ داده، از اصلاح کردن و آپدیتِ فایل‌های مشترک جلوگیری می‌کند.
- **پست‌ها**: هر پست یک فایل جدید و منحصربه‌فرد است.
- **کامنت‌ها**: هر کامنت یک فایل جدید و منحصربه‌فرد در پوشه مربوط به پست است.
- **لایک‌ها**: به جای به‌روزرسانی یک عدد شمارنده درون فایل `post.json`، هر لایک صرفاً یک فایل متنی خالی با فرمت `like_<username>.txt` است. عملیات `PutObject` و `DeleteObject` در S3 به صورت اتمیک (Atomic) انجام می‌شوند، بنابراین لایک کردن همزمان توسط چند کاربر هرگز باعث خرابی داده‌ها یا بازنویسی لایک‌های یکدیگر نمی‌شود.

## 🔐 ریلیزها و GitHub Actions

هنگامی که یک تگ نسخه جدید (مثلاً `v1.0.0-beta.1`) پوش (push) می‌شود، GitHub Actions به طور خودکار:
۱. فایل اندروید APK را بیلد کرده و امضا (Sign) می‌کند (با استفاده از `release.jks` از طریق متغیرهای Secrets).
۲. فایل نصبی ویندوز `.exe` را با استفاده از PyInstaller می‌سازد.
۳. یک ریلیز جدید در گیت‌هاب ایجاد کرده و هر دو فایل را به آن پیوست می‌کند.

برای آموزش تنظیمِ secretهای مربوط به امضای اندروید (Signing)، به فایل `keystore/README.md` مراجعه کنید.
